# 行程版本：行程生成、验证与局部调整

阅读顺序：`travel-plan.ts` → `auto-plan.ts` → `plan-validator.ts` → `plan.service.ts` → `PlanPanel.vue`。

## 调用链

用户/Agent选择真实候选 → 纯函数初排 → 独立预算 → 独立约束验证 → immutable PlanVersion → 事务保存并切换当前指针。

初排优先放入真实交通时刻；自驾根据真实驾驶分钟分段加入休息/充电；跟团使用已提供的逐日安排，缺安排则标待确认。自由行按最近邻与开放窗口放景点，游览90分钟和点间30分钟均标为估算。酒店必须明确选择；不会把搜索第一条当作已预订酒店。

## 为什么生成与验证分开

模型或初排算法只能提出草案。验证器独立检查日期连续、时区、时间与接驳冲突、地理下限、开放窗口/闭园、预约、无障碍、步行/驾驶上限、老人儿童、必去点、交通库存、产品归属、费用和来源。实际道路时间不能用直线距离代替；跨时区航班、午夜交通和停靠点需要进一步核实。

状态是 `validated / needs_confirmation / invalid`。允许保存有问题的草案以便学习调整，但不会把它标成通过。`validated` 也不代表已经预订、出票或预约。

## 版本与比较

局部替换重新验证整份草案和费用并生成子版本，原版本不会UPDATE。每个版本冻结选中报价、汇率、预备金、证据和需求条件指纹。回退只改指针；报价不会因回退而延长有效期。

比较在当前条件下重新检查过期与口径；日期、人数、标准不同或资料不完整时拒绝排名。实时报价和估算不混排。显示改动日期、费用、时长和不能排名的原因。

接口：`POST /trips/:id/plans`、`/generate`、`/replace`、`/compare`，`GET /plans/:versionId`、`POST /plans/:versionId/activate`。输入不接受客户端自报 budget/status。

测试覆盖冲突定位、真实候选绑定、不可变报价/来源、版本替换、回退、越权和比较。
