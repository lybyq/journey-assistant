# 第三模块：持久化对话与实时运行

已实现多轮消息、消息分页、会话恢复、公开执行轨迹、实时增量、游标补发、心跳、取消、幂等、并发配额、硬超时、输出上限和慢客户端背压。当前执行器只调用真实 `system.health`，不调用语言模型，不生成旅游报价；第四模块负责接入 Deep Agents。

## 数据与一致性

新增迁移 `0002_conversation_runtime.sql`，保留第一条迁移原样。`runs` 保存用户、登录会话、幂等请求标识、运行状态、取消标志、租约和输出计数；`messages` 保存用户原文及助手已公开正文；`run_events` 按会话连续序号保存公开事件。会话行记录消息位置和事件水位。

创建运行、两条消息及开始事件在一个事务中提交。每次增量把事件与助手正文在同一事务内提交。追加先锁会话再锁运行；快照也持有短会话锁，因此快照正文与水位一致。运行终态只能从 `running` 进入一次；成功、取消、超时和租约恢复竞争时由数据库行锁裁决。

同用户的 `requestId` 唯一。相同会话、相同原文重试返回原运行；改变会话或原文返回409。数据库部分唯一索引保证每个用户和每个会话最多一个活动运行，启动事务再限制全部实例合计最多20个。归档会话允许查询历史，启动新运行返回409。

## HTTP 接口

所有接口位于 `/api/v1`，要求 `Authorization: Bearer <短期访问令牌>`。令牌不进入 URL。所有资源访问先按真实登录用户检查会话归属，客户端不能提交 `userId`、任意工具名或系统提示词。

| 接口 | 请求与响应 |
| --- | --- |
| `GET /conversations/:id/messages` | `limit=2..50`，默认30；`before`为本会话消息ID。正文按自然顺序返回，另有 `nextCursor`、最新 `run`、最新轮全部 `events` 和一致性 `sequence` |
| `POST /conversations/:id/runs` | 严格请求 `{requestId,message}`，原文1～2000字；返回 `{run}` |
| `POST /conversations/:id/runs/:runId/cancel` | 幂等接受取消，最终状态通过事件或快照确认；跨用户404 |
| `GET /conversations/:id/events?after=0` | 标准SSE帧，由fetch读取并附加Bearer；仅补发 `sequence > after` 的事件；未来游标400 |

生产实时通道采用流式HTTP，而第一模块 `/ws/chat` 仍保留为受开发开关控制的匿名底座诊断。它们生命周期与序号语义不同，网页已经切换到身份绑定的生产通道。未来小程序需要单独实现流读取或增加经过鉴权的WebSocket适配器，不能直接复用浏览器fetch实现。

## 恢复流程

1. 登录后加载当前用户资料和会话。浏览器 `sessionStorage` 仅记住按账户隔离的选中会话ID；所有权仍由后端重新校验。消息、工具轨迹和访问令牌不写浏览器存储。
2. 读取一致性快照，用最新轮事件从空状态重建正文与工具轨迹，以快照水位作为已确认游标。历史列表排除最新轮，避免正文显示两遍。
3. 打开 `events?after=<水位>`。只在完整事件解析、归约成功后移动游标；重复序号忽略，序号间隙触发补发。UTF-8解析支持中文跨字节分块。
4. 网络断线后最多自动重试8次，退避1～15秒；仍失败则显示手动重连。后台运行继续受服务端租约和90秒硬超时约束。重新打开页面可从数据库恢复。
5. 同账户其他页面启动新轮时，本页读取新快照，以获得真实用户输入和完整历史。

## 资源与安全边界

| 边界 | 当前限制 |
| --- | --- |
| 活动运行 | 每用户1个、每会话1个、所有API实例合计20个 |
| 实时连接 | 每用户跨实例3条，单API进程最多100条 |
| 流生命周期 | 最长25秒后轮换；每秒心跳并重新校验JWT、会话撤销和账户禁用 |
| 客户端心跳 | 10秒未收到字节则重连；正常轮换不累计故障重试次数 |
| 背压 | 每批最多64个事件；`write=false` 后等待drain最多5秒，不继续堆积事件 |
| 单轮输出 | 最多32KiB UTF-8正文、512条事件，其中为终态预留位置 |
| 单条事件 | 最大16KiB JSON，工具输出仍必须符合白名单schema |
| 消息分页 | 单页最多50条；网页历史窗口最多约200条，重新打开会话释放内存 |
| 执行时间 | 每轮90秒硬超时；当前每个增量发布前检查会话、取消标志并续租15秒 |
| 崩溃恢复 | 每5秒扫描过期租约，写入唯一 `WORKER_INTERRUPTED` 失败事件；不偷偷重跑工具 |
| 槽位回收 | Redis有序集合原子限流，失联连接槽位45秒过期；正常断开立即删除 |

用户停止时立即传播本进程 `AbortSignal`；其他实例通过数据库取消标志在下次执行检查时停止。登出会撤销访问JWT、关闭长流并使当前实际工作停止。第四模块引入长模型和工具调用时，必须持续续租并把同一个信号传给SDK，不能只停止前端显示。

现在的恢复是“消息与公开事件恢复”。进程崩溃后当前任务明确失败，不承诺从某个模型token继续执行；LangGraph checkpointer与可恢复模型编排属于第四模块。
