# 国内商品平台申请与接入路径

核实日期：2026-10-31。当前用户没有上述开放平台账号；没有提交申请或取得商品生产权限。产品范围为中国内地、各类个人出行，商业模式是免费规划＋预订导流，由平台完成订单、付款和售后。本文列申请路径，不代表适配器已实现；聚合验收见[核心Spec](specs/domestic-offer-aggregation.md)。

## 先申请什么

优先申请美团个人开发者验证辅助查询，同时咨询美团酒店门票分销与艺龙/同程酒店合作，目标是两个独立生产报价来源。携程分销作为并行候选。餐饮另向美团联盟询问到店商品范围与Web导流/API权限，不用酒店账号推导餐饮能力。

美团个人开发者路径有官方明确说明；其余表中的主体条件、费用、保证金、流量门槛、审核时长、品类范围及Web外部展示权限均应以对应平台当前审核和协议为准。公开入口未完整披露的条件标为待确认，不承诺个人一定可申请，也不把企业主体或某种许可证说成所有渠道统一要求。

## 申请前准备的材料

以下是本项目建议准备的沟通材料，不是声称每个平台都强制要求：

- 产品名、产品说明、演示页面或截图，说明国内规划、对比和免费导流模式；当前无真实用户/流量时如实填写开发中，不编造业务数据。
- 当前个人/企业主体情况和联系方式；若平台只接受企业，再核实营业执照、结算等具体要求，不为一个入口预先承诺所有资质。
- 计划上线的Web域名及后端出口IP；本机127.0.0.1演示地址不能当作平台可访问的线上地址。备案、回调、HTTPS等按实际部署和平台要求落实。
- 首批城市、酒店/餐饮/门票品类和预期请求量；希望先获测试环境，再按真实访问量申请生产额度。
- 方案/商品比较页面，说明需要同时展示其他渠道、来源时间、完整价格条件及退改，不把佣金混入适合度排序。

## 申请时可以复制的需求说明

> 我们正在开发国内智能旅行规划Web产品，为不同出行人群生成可调整行程，商业模式为免费规划＋预订导流，订单、付款和售后由合作平台完成。希望申请贵平台的酒店/餐饮套餐/门票中适用的品类能力。需要按日期、人数、房间或票种等条件搜索商品、获取结构化报价和规则、在用户点击前确认价格，并生成带条件和归因的商品跳转链接。请确认个人或企业的准入要求、是否允许在外部Web与其他渠道并列展示报价、测试/生产申请流程、配额、费用及可提供的文档。当前处于开发阶段，无需本方代收款或自动下单。若API查询和H5跳转无法结合，也请说明可行合作方式。

以上只是供用户提交的草稿，本项目未替用户发送邮件、提交表单或签署协议。

## 商务回复后必须核对

1. 是否允许本产品的多用户Web场景，而非仅本人Agent或商家内部工具。
2. 是否有结构化酒店房型/餐饮套餐/门票SKU，还是内容回答、首页活动或推广券包。
3. 是否允许同时展示其他渠道及缓存商品资料；缓存期限、来源标识和图片/点评使用要求是什么。
4. 金额是起价、单晚价、全程价还是批发净价；是否包含必要费用，是否依赖会员/优惠券。
5. 查询、实时验价、取链、成交归因各自是否开通；可否在平台完成交易，链接能否携带日期人数等条件。
6. 错误码、限额、超时、价格变化、售罄和生产环境验收如何处理；没有确认的能力不写为已开通。

如果只有联盟取链权限，可先验收商品导流；不能据此验收实时报价。如果只有API价格但没有获准交接链接，也不能宣称已经打通免费规划＋平台预订。

## 获批后的代码接入顺序

后端供应商适配器负责鉴权、限速、超时、响应归一和来源记录；DeepAgents调用本项目的受控业务工具，前端只接收业务数据，不持有供应商密钥。供应商没有MCP也可以直接用正式HTTP API，不必再找第三方MCP代理。

先核对获批版本文档和脱敏样本→实现实际适配器→把供应商实体映射到酒店/门店/景区→按SKU与条件生成报价→至少两个独立生产渠道做同条件比较→确认商品交接→实际生产验收。不能靠AI从文字起价中猜房型库存。

美团个人Token仅用于经许可的辅助能力，不能用作面向所有用户的共用乘客或预订身份。凭证由用户保存在本机忽略的服务端环境文件/部署秘密管理中，不发聊天、不提交Git；当前代码未实现美团适配器，因此没有凭空新增一个看似可用的配置项。

没有账号也可继续开发实体/SKU/条件模型、比较引擎、费用与行程联动、错误隔离和界面；协议fixture只能验证代码。生产库存、实际商品跳转和跨渠道生产比价必须等实际授权后联调，始终单独报告状态。

## 官方文档的新旧版本处理

- 艺龙旧`hotel.list`已标注废弃，获批后按现行搜索文档接入。其[2026-09-17公告](https://open.elong.com/notice/detail?id=391)区分用户实时详情与预抓缓存详情，接入时须按用途申请对应权限和QPS，不能一个接口承担全站预抓取。
- 携程旅游旧公告链接至新版`open.trip.com`，文档版本和品类权限以商务与获批控制台为准。
- 道旅[内容API v2](https://apidoc.didatravel.com/content-api-v2/how-to-use-content-api.html)与价格查询并非同一种接口；公共测试账号内容范围有限，仅用来验证协议。

上面的入口和能力来自官方公开页面，实际费用、审批时间与是否接受当前主体未完整公开，本文没有编造固定报价或开通承诺。
