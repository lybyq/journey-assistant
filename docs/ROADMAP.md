# 总体方案与模块实施顺序

## 产品范围

目标是完整的旅行决策与规划助手，支持自由行、自驾、跟团三种模式，贯穿需求澄清、资料检索、交通、住宿、游玩、预算、比价、逐日行程和调整。方案必须给出数据出处、查询时间、报价条件和估算边界。

完整设计一次确定，代码按模块交付。**目前已完成 01～05；未经用户要求不开始 06～14。**

## 技术选择

- Node.js + NestJS：模块、依赖注入、HTTP、WebSocket 与 OpenAPI。
- 全程 TypeScript：应用、配置代码、协议与测试；标准 JSON/YAML 仅用于工具配置。
- Deep Agents + LangChain + LangGraph：模型工具循环、任务拆解、上下文与后续持久化执行。
- MCP adapters 2.x：12306、高德、Tavily 及后续批准的服务。
- Vue 3 + Vite + Pinia + Vue Router：先完成 Web，再通过新客户端适配微信小程序。
- PostgreSQL：用户、会话、偏好、方案、报价证据与审计数据。
- Redis：缓存、限流、任务状态及短期事件转发；不是长期报价真相来源。
- 授权供应商 HTTP API：酒店、机票、租车、旅行团的具体日期报价与库存。没有 MCP 的 API 直接封装 LangChain Tool。

## 01 工程底座（当前已实现）

**目标：** 所有后续模块有统一的工程、协议、配置和交互容器。

**实现：** 单仓库、依赖锁、严格 TS、Nest 模块、配置校验、健康探针、错误边界、请求追踪、开发 OpenAPI、原生 WebSocket 诊断、Vue 工作台、Markdown 安全渲染、真实工具轨迹、模块路线。

**边界：** SDK 只提供装配工厂；不执行模型、MCP 或旅游交易。不把演示数据当真实业务，不生成虚假用户历史。

**验收：** 无密钥可运行；真实自检返回系统数据；流式、取消、错误和来源限制通过测试；桌面与手机布局可用。

## 02 用户、存储与数据归属（当前已实现）

**依赖：** 01。

**实现：** PostgreSQL 迁移与 ORM、Redis 生命周期、用户注册/登录与刷新、密码哈希或批准的身份供应商、会话归属、旅行者资料、服务端访问控制。浏览器凭据策略明确选择，不能把长期令牌散落在组件里。

**主要实体：** User、Credential、RefreshSession、Conversation、TravelerProfile、AuditEvent。

**接口：** `/auth/*`、`/me`、`/conversations`。所有查询按用户归属过滤。

**验收：** 数据库迁移可重复部署；用户 A 不能查看或取消 B 的会话；退出与令牌撤销有效；日志不输出秘密值。

## 03 生产对话与实时运行（当前已实现）

**依赖：** 02。

**实现：** 多轮历史、消息分页、会话恢复、运行标识、事件持久化序号、断线按游标补发、心跳、取消、并发配额、超时与背压。由开发诊断扩展为身份绑定的业务运行通道。

**主要实体：** Message、Run、RunEvent；连接绑定 userId/conversationId，不能信任客户端自报归属。

**验收：** 断线补发不重复拼接；刷新保留历史；终态只有一个；取消中止实际执行器；04接入模型时继续传递同一AbortSignal；大输出不会无限占用内存。

## 04 Deep Agents 智能体编排（已实现；独立学习文档见 MODULE-04-AGENT.md）

**依赖：** 03。

**实现：** 模型供应商适配、真实流事件映射、任务计划、受控子任务、上下文裁剪、Postgres LangGraph checkpointer、执行预算、明确失败后的同会话重提与版本化提示词。内部推理不作为公开事件发送。

**输入：** 用户消息、已授权历史、偏好与已验证工具集合。

**输出：** 公开计划摘要、步骤进度、工具调用和最终正文；不接受客户端直接注入 systemPrompt。

**验收：** 未配置模型时明确报错；模型调用有超时/配额；步骤来自真实执行；会话记忆隔离；没有工具证据时不编造价格。

## 05 MCP 管理与工具执行（已实现；独立学习文档见 MODULE-05-MCP.md）

**依赖：** 04；基础适配器工厂已在 01 预留。

**实现：** 12306、高德、Tavily，连接发现、命名空间、工具白名单、schema 校验、生命周期、超时、断路、重连、输出裁剪、参数/响应脱敏。远程页面内容作为不可信资料，不接受其指令提升权限。

**配置：** 本地 stdio 与远程 HTTP/SSE 独立定义；服务端保存密钥；ModelScope 介绍页不能直接当 MCP endpoint。

**验收：** 每个工具有真实开始/完成/失败事件；配置状态与连接状态分开；单供应商故障不会假装所有数据可用；退出关闭子进程与连接。

## 06 旅行画像与需求澄清

**依赖：** 04、05。

**实现：** 出发地、目的地、日期、成人/儿童、天数、总预算/人均预算、住宿房间、车辆、旅行节奏、老人儿童限制、饮食与必去点位。明确追问缺失的关键条件。

**主要结构：** TripRequest，日期统一 `Asia/Shanghai` 解释并保留目的地当地时区，避免模型按服务器时区猜日期。

**验收：** “两大一小”“人均预算”“三天两晚”标准化准确；预算范围与人数口径清楚；不偷偷把未知条件填成事实。

## 07 旅游资料与证据检索

**依赖：** 05、06。

**实现：** Tavily Search → Extract，优先官方景区/交通公告、来源去重、发布时间与查询时间、营业日/闭园/预约条件、证据关联、时效缓存。

**主要实体：** Source、Evidence、Claim。文章发布日不能冒充报价查询时间。

**验收：** 回答关键结论可回溯原文；抓取失败明确缺失；网页“起价”标成广告/页面价；网页内容不能注入额外工具指令。

## 08 城际交通与落地接驳

**依赖：** 05～07。

**实现：** 12306 车站编码、查询范围、车次、余票、换乘；经批准的航班报价接口；门到门接驳、高德站点定位与市内交通。

**主要结构：** TransportOption，包含出发/到达时间、时区、换乘、票种、报价条件与可用性。

**验收：** 不只比较票面价格，也比较到站接驳与总耗时；日期超出可售范围明确提示；查询和下单严格区分。

## 09 自驾与车辆费用

**依赖：** 06～08。

**实现：** 途经点路线、距离/耗时、日驾驶上限、休息站、油耗/电耗、能源单价、过路费、停车费、充电与租车的保险条件。

**计算：** 燃油费按里程×百公里油耗÷100×油价；电费按里程×百公里电耗÷100×电价；单价来源与估算假设都保留。

**验收：** 不把平均油价或估算路费写成实时报价；车辆总费与人数分摊分开；晚到、疲劳驾驶和充电时间计入行程可行性。

## 10 住宿、门票与餐饮

**依赖：** 06～09。

**实现：** 酒店指定入住日与离店日、房型、间数、成人儿童、早餐/税费/取消条款；景区票种、预约与营业时间；餐饮预算和位置。

**数据来源：** 授权供应商报价 API + 官网资料；搜索结果只作为补充证据。

**验收：** 每晚房价不能误当全程价；每间价不能误当每人价；库存、退款条款和强制费用标注清楚。

## 11 旅行团与产品条款

**依赖：** 06、07、10。

**实现：** 团期、出发地、人数、产品总价、酒店标准、包含/不包含、单房差、自费、购物点、接送、导游服务与取消条件。

**输出：** 标准化 TourProduct 与证据链接；同名线路不直接视为同一商品。

**验收：** 拆出营销“起价”与指定团期报价；缺失费用列为待确认；不宣称搜索已覆盖全部平台或找到全网最低价。

## 12 确定性预算与价格对比

**依赖：** 08～11。

**实现：** 独立金额计算服务，以整数最小货币单位或十进制定点处理；币种、汇率来源、间数、晚数、成人儿童、包含项、强制费用、可选项目与预备金。

**主要结构：** PriceQuote、CostItem、CostBreakdown、Comparison；价格分类 `live_quote / advertised / estimate / unknown`，包含 `checkedAt / validUntil / source / conditions`。

**口径：** 同日期、人数、天数、住宿标准和费用范围后再比较；按约束选择最便宜/最省时/最舒适，不只按低起价排名。

**验收：** 模型只解释，不负责心算；币种不同先转换且可追溯；缺失价格是 unknown 而不是 0；计算可复算，不能重复计算已包含门票/交通。

## 13 行程生成、验证与局部调整

**依赖：** 06～12。

**实现：** 按天编排点位、交通、用餐、住宿、预约、开放时间、时间缓冲；生成自由行/自驾/跟团可比方案；替换酒店/景点时局部重新计算，保留版本差异。

**主要实体：** TripPlan、PlanVersion、DayPlan、ScheduleItem、ConstraintViolation。

**验收：** 方案通过时间冲突、地理距离、营业时间、预算和乘员限制验证；不可行时解释冲突并提供调整；旧方案不被静默覆盖。

## 14 可视化交付与上线保障

**依赖：** 前面全部模块。

**实现：** 逐日时间轴、地图路线、交通与价格对比、来源抽屉、版本回退、分享访问控制、Markdown/PDF 导出、供应商深链；审计、限流、监控、成本统计、提示注入防护、备份、部署和质量评估。

**交互：** 展示公开计划、实际步骤、脱敏工具参数和返回值；原始数据折叠；最终回答以 Markdown 与结构化旅行卡片共同呈现。

**验收：** 分享不能越权；密钥不进入网页与导出；长任务可取消与恢复；供应商限流可降级；旅行质量、价格证据与模型成本有可追踪指标。

## Web 完成后的微信小程序适配

新增小程序客户端，而不是假设标准 Vue 网页可以直接编译为微信小程序。评估 Vue 3 + Vite 的 uni-app 入口；复用共享协议、纯状态归约器、业务数据结构与后端 API。替换 WebSocket、路由、剪贴板、Markdown 渲染和地图适配，处理合法域名、WSS、登录与平台权限。此阶段不在当前 01 的实施范围。

## 供应商依赖与现实边界

实际机票/酒店/旅行团库存通常需要供应商授权、合同或账户权限；没有这些条件时明确标记能力未接入，不伪造库存。第一模块不会向用户索要 Key，因为当前任务不需要调用外部服务。
